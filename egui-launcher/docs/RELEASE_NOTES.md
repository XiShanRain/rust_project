### 四、Tab 双口径与提交即学别名（批次 G）

`Tab` 现在承担两件事，分工方式由设置页「Tab 键行为」决定：

| 口径 | `Tab` | `Shift+Tab` | 说明 |
| --- | --- | --- | --- |
| 补全优先（默认） | ~~查询词是选中项**名称或别名前缀**时补全整词，否则循环选中下一项~~【批次 H 改判】查询词**只在「能被它补长的候选恰好一条」时**补全整词，候选≥2 时不猜、改为循环选中下一项 | 循环选中上一项 | `jsq` → `计算器`（唯一候选，照补）；`Tas` 有 Task Manager 与 Task Scheduler 两条 ⇒ 只移动不补 |
| 专职导航 | 循环选中下一项 | 循环选中上一项 | Delphi 版 ALTRun 口径，代价是没有补全 |

- 两种口径下循环都**到头回绕**（区别于 `↑↓` 的两端钳位）。
- 补全与循环都用可观测状态判定，不依赖按键时序，因此不需要用户记住"连按"这类隐藏手势。
- 提交即学别名（对标 Delphi）：`Enter` / 双击 / 数字键执行成功后，把本次查询词追加进该条目的别名字段。门槛：长度 ≥2、不等于名称、不与已有别名重复；学习随执行那一次落盘，不额外写文件。
- 别名支持空格分隔多个触发码：`MatchKeys` 由单个别名改为按词建键，避免 `"jsq qsj"` 被当成一个键算出假的首字母分数。

### 五、Tab 补全改甲案与 `Ctrl+J` / `Ctrl+K`（批次 H）

起因是真人复测报的缺陷：输入 `Tas` 出 7 条（含 Task Manager、Task Scheduler），按 Tab 补成 Task Manager 后列表塌成 1 行，真正想要的 Task Scheduler 反而够不着。

根因不在"补完不能循环"，而在判据只看选中项：**列表是查询的派生值**，查询一旦被写成某一条的完整名称，派生结果必然只剩它自己。

三个候选方案（用户点甲）：

| 方案 | 做法 | 结论 |
| --- | --- | --- |
| 甲＝无歧义才补 | 数「可被该查询补长」的候选，恰好 1 条才补，≥2 条交给导航 | **采纳**：代价最小、无新状态，`Tas` 场景按键数比旧版更少 |
| 乙＝补到最长公共前缀 | `Tas` → `Task `，候选集保住（bash 口径） | 未采纳：多一个函数与尾随空格的多词解析风险，条目名短、收益小 |
| 丙＝补全后循环候选集 | 记住补全前的集合，Tab 在其中循环，一圈后恢复原词（zsh menu-complete，即用户最初提法） | 未采纳：唯一要引入"按键历史状态"的方案，违反已入档的「分流只看可观测状态」判据 |

- 落地为 `matching::unique_completion(查询, 清单, 结果集)`；`Shift+Tab` 与「专职导航」口径不变，`jsq` → `计算器` 这类唯一别名的补全保留。
- 新增 `Ctrl+J` / `Ctrl+K` ＝ 循环下一项 / 上一项，**恒为导航**、不会被补全抢走，与 `Tab`/`Shift+Tab` 的导航那半同为到头回绕（区别于 `↑↓` 的两端钳位）。用户原点名 `Ctrl+N` / `Ctrl+P`，与「新建」「置顶」冲突，改选空闲键。
- 顺带纠正需求书附录 A 的一处记账错误：`Ctrl+P/N` 此前被记成"已落地并实测"，实际从未实现（`Ctrl+P` 是置顶、`Ctrl+N` 是新建）。

### 七、批次 H 两条遗留的修复（批次 I，2026-10-18 用户裁定"两条都修"）

| 缺陷 | 症状 | 修法 | 实测 |
| --- | --- | --- | --- |
| 启动路径不走 `on_show()` | 冷启动后第一次打字被中文输入法截走，字母进不了搜索框（焦点本来是好的） | `new()` 末尾按"首屏就是搜索页"的判据补调一次 `on_show()`；判据取 `focus_query`，弹窗或设置页启动时不抢它们的焦点 | 冷启动日志直接出现 `IME→English: before open=false conv=0x1 → after open=false conv=0x0`，全程没有任何呼出动作 |
| 补全后光标停在旧长度处 | `task sch` 补成 `Task Scheduler` 后接着打字会插进词中（`Task Schxeduler`） | 补全那一支顺手写 TextEdit 状态：`TextEditState::load` → `cursor.set_char_range(Some(CCursorRange::one(CCursor::new(字符数))))` → `store` 回去 | 补全后注入 `x` ⇒ 搜索框 `Task Schedulerx`、提示行 `未找到「Task Schedulerx」`，光标在词尾 |

- egui 0.36.2 的公开路径记档：`TextEditState` 在 `egui::widgets::text_edit::`（crate 根路径没有），`CCursorRange` 与 `CCursor` 在 `egui::text::`；`CCursor::new` 收 `impl Into<CharIndex>`，而 `CharIndex` 是 **`usize`** 包装 —— 写 `chars as i32` 编译不过。搜索框的 widget `Id` 因此提成 `search_field_id()`，快捷键分支与 widget 两处必须同一个键。
- 一条测试环境事实：本轮真人复测期间 `settings.json` 被改成 `tab_mode = navigate`，该口径下 Tab 恒为导航 ⇒ 补全与"补全后光标"都不可能触发，这是用户复测发现不了第二条缺陷的直接原因（第一条则因为输入法当时在英文态而复现不出）。

### 八、空格执行改四档（批次 J，2026-10-18）

需求来自用户："Delphi 版的 ALTRun 用空格代替 Enter，单手就能启动程序"。原来的两态布尔（开＝任何时候执行 / 关＝只有输入框为空时执行）中间缺了最顺手的那一档：**打着字时空格永远是空格，只有这个词已经指准了才执行**。

**对标结论更正**：本轮交叉核对 Delphi 版源码（三条独立路径：窗体 `KeyPress` / `FormKeyDown` / 列表控件事件处理）后确认，**Delphi 版 ALTRun 根本没有"空格执行"**——它的执行键只有 `Enter` 与双击。此前需求书与本文件把"空格执行"记成"对标 Delphi"是错的，本条更正保留旧记录不删除。因此四档的判据不是抄来的，是按本项目自己的已入档判据（**分流只看可观测状态，不看按键历史**，与批次 H 的 Tab 甲案同一条）重新设计的。

| 档位 `space_to_run` | 空格执行的条件 | 适合谁 |
| --- | --- | --- |
| `word`（默认） | 查询词**已经是**选中项的名称、或它的某一个空格分隔的别名（去首尾空格、忽略大小写）；或输入框本来就是空的 | 想要"打全名 / Tab 补全后直接空格运行"，同时打半个词时空格还能当空格用 |
| `unique` | 结果集只剩 1 条；或输入框本来就是空的 | 想要"搜到唯一一条就闭眼按空格" |
| `off` | 只有输入框为空时（＝旧版 `false`） | 保持旧行为 |
| `always` | 任何时候（＝旧版 `true`） | 保持旧行为 |

- 判据全部落在纯函数 `matching::space_executes(档位, 原始查询, 清单, 结果集, 选中行)`，单元测试给了一张真值表；`word` 档另配 `matching::query_is_full_word`。
- **"框是空的"分两种口径**：`word` / `unique` 只在原始串真正 `is_empty()` 时算空框——这样"为了打词中空格而故意先敲的那个空格"不会提前触发执行；`off` / `always` 沿用旧版的 `trim().is_empty()`，不改已交付行为。
- **`Shift+空格` 是逃生舱**：任何档位下，`Shift+空格` 一律当普通空格插入。实现上必须先 `consume_key(SHIFT, Space)` 再看 `consume_key(NONE, Space)`——egui 的 `Modifiers::NONE` 用 `matches_logically` 判定，会连 `Shift+Space` 一起吃掉（记忆里入档过的同一个坑）。
- 兼容旧 `settings.json`：`#[serde(untagged)]` 的 `SpaceRunWire { Legacy(bool), Name(String) }`，`false`→`off`、`true`→`always`，缺字段→`word`；未知字符串（如 `"wod"`）报错而不是静默兜底，实测日志会顶出「未知的 space_to_run 档位」。
- 设置页由 1 个复选框换成 4 个 `selectable_value` 单选，配 4 行说明；点选即写盘并记 `设置页：space_to_run = word（已写 settings.json）`。

### 九、同档位内的学习排序做成两档（批次 K，2026-10-18）

需求来自用户实测的一句："一直没执行『命令提示符』，只执行了一次，就跑到执行了多次的『记事本』前面了，这样是不是不科学"。

**改动前的次序算法**（`matching::MatchIndex::search`，逐键短路，前一个相等才比下一个）：

1. **匹配档位**（全词精确 100 → 前缀 90 → 词首 80 → 首字母 75 → 包含 60 → 多词 45 → 子序列 30，硬第一主键）；
2. **置顶** `pinned`；
3. **最近一次使用时间** `last_used_ms`（越新越前）；
4. **累计次数** `use_count`；
5. 带内连续分（位置惩罚、长度惩罚）；
6. 名称更短的。

第 3、4 键的顺序就是用户看到的症状根源：**"最近一次"排在"次数"前面**。记事本 8 次、命令提示符 3 次（这 3 次里有 2 次是我做注入测试时按的，不是真实使用），只要后者最后那次晚 117 毫秒，它就在同档位内压住前者——而且这个位置是**单向的**：记事本之后再被选中一次也不会掉回去，除非命令提示符又被用一次。空输入框的浏览视图用的就是这一层，所以"打开就看到的头几行"同样被它决定。

用户裁定：**两种口径都实现、做成设置页开关、默认甲**。

| 档位 `learn_rank` | 同档位内的比较键 | 代价 |
| --- | --- | --- |
| `count`（甲，默认） | 累计次数 → 最近一次 | 一周没碰的老项会长期占着前排，"刚用过一次"挤不掉它 |
| `decay`（乙） | 热度 = `log2(1 + 次数) × 0.5^(距上次使用天数 / 7)` → 最近一次 | 多算一次对数与幂；半衰期 7 天是拍的常量，需要按实际手感调 |

- **档位仍是硬第一键**：`置顶 → 学习层 → 带内分 → 短名` 全在档位之后，时间戳一个字都不进打分与分档。这条是 FR-QRY-07 裁定 a 的原话（时间戳只允许作同分带内的学习位序键，不得改门槛、不得改分档），两档都守它。
- **实现成"比大小"而不是"加分"**，是为了避开早先讨论过的那版加和公式（`匹配分 × 1000 + 热度`）：档位之间只差 5～70 分，一旦把次数加进同一根数轴，用得多就能把匹配更准的项顶掉，等于绕过裁定 a。开发计划第 404 行继承表里那条"学习排序只加在排名上"讲的正是同一件事。
- **对 `8·ln(1+count)` 与 `e^(-days/30)` 的取舍**：本仓库存的参考项目公式是 `Boost = 8·ln(1+count) + 近 7 天 +5 + 该输入或其前缀选过它 ≤+60`（开发计划第 206、404 行）。① 对数项同形，只比大小时 `log2` 与 `8·ln` 差一个常数因子、结论一致，取 `log2` 是为了让"次数 1→0、3→2、8→3.17"这种量级一眼可读；② 时间项**故意不照抄**——"近 7 天 +5"是台阶加分，用了 50 次的项（`8·ln51≈31`）加不加 5 都一样排，永远塌不下去，这正是用户这次报的"赖在前面"的另一半边；改成**乘**一个真半衰期，老项的整体热度才随时间衰减，`0.5^(days/7)` 的名义值与实际半衰期相等（`e^(-days/30)` 的真实半衰期是 43.2 天，名不符实）；③ 第三项"该输入或其前缀选过它"要按查询串另存一张历史表，本批未做——已有的"提交即学别名"是它的更强替代（学成别名后下次直接进更高档位，不是同档位内加分）。本轮**没有**回读 AHK/Delphi 源码复核原式（参考目录在工作区外，权限层拦住了），依据是仓库内那份记录。
- **旧 `settings.json` 没有 `learn_rank`** ⇒ `serde(default)` 落甲档；`"decayy"` 这种拼错报错而不是静默兜底，与批次 J 的 `space_to_run` 同一口径。
- **键位口径**：这是设置页开关，与 `space_to_run`、`tab_mode` 同批不另配快捷键，路径 `Ctrl+,` → 「通用」→ 鼠标点选（沿用批次 F 撤销 `Ctrl+S` 时定的"开关类不占键位"）。置顶入口 `Ctrl+P` 在两档下都压过学习层，想钉住某个条目用它。
- `now_ms()` 只喂这一层：它不参与打分、不参与分档，也不写盘。

### 二、单实例协议（FR-WIN-07）

1. 启动时抢占命名互斥体 `Local\XiShan.EguiLauncher.SingleInstance`。
2. 抢到即为主实例；未抢到则通过消息窗口 + `WM_COPYDATA` 把命令行交接给在跑实例，自身退出。
3. 2 秒无应答判定旧实例卡死：定位窗口所属进程、结束旧实例，再重新抢占互斥体接管。
4. 旧实例刚退出（暂时无窗口）时短重试；仍无窗口则降级启动，不弹错误。

补充约束：

- 探测句柄在确认「已有实例」后立即关闭，避免旧实例被杀后互斥体仍被吊住。
- 主实例句柄保持打开，直到进程退出。

### 三、命令行协议（FR-WIN-08）

| 参数 | 行为 |
| --- | --- |
| `-Startup` | 静默启动到托盘，不抢焦点；已有实例在跑则直接退出 |
| `-SendTo <路径…>` | 1 条：打开预填编辑框；多条：批量添加并去重，Toast 显示新增 / 跳过数 |

资源管理器「发送到」追加的裸路径（无 `-SendTo` 前缀）同样按 SendTo 处理。
