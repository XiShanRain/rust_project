### 四、Tab 双口径与提交即学别名（批次 G）

`Tab` 现在承担两件事，分工方式由设置页「Tab 键行为」决定：

| 口径 | `Tab` | `Shift+Tab` | 说明 |
| --- | --- | --- | --- |
| 补全优先（默认） | ~~查询词是选中项**名称或别名前缀**时补全整词，否则循环选中下一项~~【批次 H 改判】查询词**只在「能被它补长的候选恰好一条」时**补全整词，候选≥2 时不猜、改为循环选中下一项 | 循环选中上一项 | `jsq` → `计算器`（唯一候选，照补）；`Tas` 有 Task Manager 与 Task Scheduler 两条 ⇒ 只移动不补 |
| 专职导航 | 循环选中下一项 | 循环选中上一项 | Delphi 版 ALTRun 口径，代价是没有补全 |

- 两种口径下循环都**到头回绕**（区别于 `↑↓` 的两端钳位）。
- 补全与循环都用可观测状态判定，不依赖按键时序，因此不需要用户记住"连按"这类隐藏手势。
- 提交即学别名（对标 Delphi）：`Enter` / 双击 / 数字键执行成功后，把本次查询词追加进该条目的别名字段。门槛：长度 ≥2、不等于名称、不与已有别名重复；学习随执行那一次落盘，不额外写文件。
- 别名支持空格分隔多个触发码：`MatchKeys` 由单个别名改为按词建键，避免 `"jsq qsj"` 被当成一个键算出假的首字母分数。

### 五、Tab 补全改甲案与 `Ctrl+J` / `Ctrl+K`（批次 H）

起因是真人复测报的缺陷：输入 `Tas` 出 7 条（含 Task Manager、Task Scheduler），按 Tab 补成 Task Manager 后列表塌成 1 行，真正想要的 Task Scheduler 反而够不着。

根因不在"补完不能循环"，而在判据只看选中项：**列表是查询的派生值**，查询一旦被写成某一条的完整名称，派生结果必然只剩它自己。

三个候选方案（用户点甲）：

| 方案 | 做法 | 结论 |
| --- | --- | --- |
| 甲＝无歧义才补 | 数「可被该查询补长」的候选，恰好 1 条才补，≥2 条交给导航 | **采纳**：代价最小、无新状态，`Tas` 场景按键数比旧版更少 |
| 乙＝补到最长公共前缀 | `Tas` → `Task `，候选集保住（bash 口径） | 未采纳：多一个函数与尾随空格的多词解析风险，条目名短、收益小 |
| 丙＝补全后循环候选集 | 记住补全前的集合，Tab 在其中循环，一圈后恢复原词（zsh menu-complete，即用户最初提法） | 未采纳：唯一要引入"按键历史状态"的方案，违反已入档的「分流只看可观测状态」判据 |

- 落地为 `matching::unique_completion(查询, 清单, 结果集)`；`Shift+Tab` 与「专职导航」口径不变，`jsq` → `计算器` 这类唯一别名的补全保留。
- 新增 `Ctrl+J` / `Ctrl+K` ＝ 循环下一项 / 上一项，**恒为导航**、不会被补全抢走，与 `Tab`/`Shift+Tab` 的导航那半同为到头回绕（区别于 `↑↓` 的两端钳位）。用户原点名 `Ctrl+N` / `Ctrl+P`，与「新建」「置顶」冲突，改选空闲键。
- 顺带纠正需求书附录 A 的一处记账错误：`Ctrl+P/N` 此前被记成"已落地并实测"，实际从未实现（`Ctrl+P` 是置顶、`Ctrl+N` 是新建）。

### 七、批次 H 两条遗留的修复（批次 I，2026-10-18 用户裁定"两条都修"）

| 缺陷 | 症状 | 修法 | 实测 |
| --- | --- | --- | --- |
| 启动路径不走 `on_show()` | 冷启动后第一次打字被中文输入法截走，字母进不了搜索框（焦点本来是好的） | `new()` 末尾按"首屏就是搜索页"的判据补调一次 `on_show()`；判据取 `focus_query`，弹窗或设置页启动时不抢它们的焦点 | 冷启动日志直接出现 `IME→English: before open=false conv=0x1 → after open=false conv=0x0`，全程没有任何呼出动作 |
| 补全后光标停在旧长度处 | `task sch` 补成 `Task Scheduler` 后接着打字会插进词中（`Task Schxeduler`） | 补全那一支顺手写 TextEdit 状态：`TextEditState::load` → `cursor.set_char_range(Some(CCursorRange::one(CCursor::new(字符数))))` → `store` 回去 | 补全后注入 `x` ⇒ 搜索框 `Task Schedulerx`、提示行 `未找到「Task Schedulerx」`，光标在词尾 |

- egui 0.36.2 的公开路径记档：`TextEditState` 在 `egui::widgets::text_edit::`（crate 根路径没有），`CCursorRange` 与 `CCursor` 在 `egui::text::`；`CCursor::new` 收 `impl Into<CharIndex>`，而 `CharIndex` 是 **`usize`** 包装 —— 写 `chars as i32` 编译不过。搜索框的 widget `Id` 因此提成 `search_field_id()`，快捷键分支与 widget 两处必须同一个键。
- 一条测试环境事实：本轮真人复测期间 `settings.json` 被改成 `tab_mode = navigate`，该口径下 Tab 恒为导航 ⇒ 补全与"补全后光标"都不可能触发，这是用户复测发现不了第二条缺陷的直接原因（第一条则因为输入法当时在英文态而复现不出）。

### 二、单实例协议（FR-WIN-07）

1. 启动时抢占命名互斥体 `Local\XiShan.EguiLauncher.SingleInstance`。
2. 抢到即为主实例；未抢到则通过消息窗口 + `WM_COPYDATA` 把命令行交接给在跑实例，自身退出。
3. 2 秒无应答判定旧实例卡死：定位窗口所属进程、结束旧实例，再重新抢占互斥体接管。
4. 旧实例刚退出（暂时无窗口）时短重试；仍无窗口则降级启动，不弹错误。

补充约束：

- 探测句柄在确认「已有实例」后立即关闭，避免旧实例被杀后互斥体仍被吊住。
- 主实例句柄保持打开，直到进程退出。

### 三、命令行协议（FR-WIN-08）

| 参数 | 行为 |
| --- | --- |
| `-Startup` | 静默启动到托盘，不抢焦点；已有实例在跑则直接退出 |
| `-SendTo <路径…>` | 1 条：打开预填编辑框；多条：批量添加并去重，Toast 显示新增 / 跳过数 |
| `-Preferences <页码>` | 1=通用、2=功能、3=快捷键；设置页已开时只切页 |
| `-Reloaded` | 等待旧实例释放（最多 2 秒）后接管或转发 |

资源管理器「发送到」追加的裸路径（无 `-SendTo` 前缀）同样按 SendTo 处理。
