## 一、为什么现在才有这张表

需求说明书 8.1 阶段一交付那一格（`:597`）白纸黑字要求：「可运行 exe + 可读配置 + **第 10 章阶段一用例全绿** + **已知缺陷清单**」。本轮对发布说明做了覆盖式检索：

| needle | 在 `docs/RELEASE_NOTES.md` 的命中行数 |
| --- | --- |
| `TC-` | 0 |
| 第 10 章 | 0 |
| 阶段一用例 | 0 |
| 回归表 | 0 |
| 已知缺陷 | 0 |
| 用例 | 12 |

那 12 行「用例」本轮逐行读到过（`:9`、`:180`、`:203`、`:268`、`:290`、`:409`、`:423`、`:428`、`:446`、`:491`、`:1118`、`:1144`），**全部指单元测试用例**，没有一条指第 10 章的 TC 编号。⇒ 结论只写到「按编号检索不到」这一层：**本批之前，仓库里不存在一份能支撑「第 10 章阶段一用例全绿」这句话的台账**。至于是不是「从未跑过」，本表不声称——历批可能用别的措辞写过，那要另外做一轮映射，本批没排上。

## 二、列的口径

- **执行面**：`自动化`＝判据能由纯函数、单测或脚本断言，不依赖人眼；`真机人工`＝需要真实 Windows 前台交互、肉眼或像素核对；两者都标时按主要那条判据归。
- **复跑前提**：把这条从「没跑」推到「能跑」缺的那一样东西。空＝现在就缺一个能起窗口的批次。
- **一手记录**：只认第 10 章**那一行自己带的**行内注记（判据是行首出现 `【` 或 `〔`）。第 5 章 FR 行的注记、发布说明里的批次级记录**不算**，另列在第六节。
