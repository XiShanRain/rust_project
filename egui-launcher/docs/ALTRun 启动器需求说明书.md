## 第 1 章 引言

### 1.1 目的

定义一款 Windows 程序启动器的完整需求，用于指导用 Rust + egui 实现该产品。产品形态为：全局热键呼出的搜索框，输入即时匹配多类数据源，回车执行，失焦自动隐藏。

本文的第二个目的，是把"参考项目实际做成了什么"固化成可验收的条款。两个参考项目的功能细节（分值表、默认值、快捷键、容错语义）是本文大量条款的直接来源，**这些细节是产品可用性的一部分，不是实现自由发挥的空间**。

### 1.2 参考项目与依据

| 项目 | 版本 | 体量 | 本文取用什么 |
| --- | --- | --- | --- |
| AHK 版 | 2026.10.12.19 | 约 21,000 行 AHK v2 | **主体**：多数据源体系、输入解析、七档打分、拼音、学习排序、操作面板、片段/剪贴板/计算器/网页搜索/书签/窗口/文件/脚本/终端/系统命令/速查/置顶最近、配置模型与容错、主题与视觉规范 |
| Delphi 版 | V1.46.7 | 项目自身约 10,600 行 Pascal | **补充**：参数标记 `{%p}/{%c}/{%wd}/{%wt}/{%wc}` 与编码类型、参数输入与历史、`@+/@-/@` 运行标志、通配符转正则、失效项校验与绝对↔相对路径批量转换、皮肤背景图与提示音 |
| 现状代码 | — | `src/main.rs` 99 行 | 被替代的原型。其"假数据 + 只有 `contains` + Esc 退出进程 + `expect()` 会 panic"四点均在本文中被明确纠正 |

### 1.3 术语与约定

| 术语 | 含义 |
| --- | --- |
| 数据源 / Provider | 一类可被搜索的条目来源（应用、片段、文件…）。本项目同义于"扩展点" |
| `ResultItem` | 所有数据源归一后的统一结果条目结构，见 4.1 |
| `Kind` | 条目类型：`file \| folder \| url \| text \| command`，决定 `Enter` 的默认语义 |
| 独占模式 | 输入形如"关键字 + 空格"（如 `clip `）时，结果只保留该数据源的条目 |
| 分值带 | 七档匹配分（100/90/80/75/60/45/30），见 5.2 |
| Provider 偏移 | 每个数据源叠加到匹配分之上的固定加分，决定跨源次序，见 5.2 的分值偏移常量表 |
| Boost | 学习排序加分 `8·ln(1+count)` + 近 7 天 +5 + 前缀命中 ≤+60 |
| 操作面板 | `→` 进入的第二层界面，展示选中条目可执行的动作 |
| `A_*` 变量 | 路径变量前缀（`A_Desktop`、`A_AppData`…），必须在字符串开头，见 4.5 |
| 呼出前窗口 | 启动器隐藏时前台的那个窗口，是粘贴/参数类功能的对象 |
| 待实测 | 该条款的实现路径尚未经最小 demo 验证，实现前必须闭环，**不当作已确认** |

## 第 2 章 产品概述

### 2.1 产品定位

一款常驻后台、按需呼出的 Windows 启动器。核心体验三句话：**按一个键，窗口出现在手边；打几个字，想要的东西排在第一位；按回车，事情办完，窗口消失。**

与参考项目的产品主张一致：轻量、快速、无遥测、可被用户完全理解和接管（配置是可读的 JSON，数据可以整个目录搬走）。

### 2.2 运行环境

| 项 | 要求 |
| --- | --- |
| 操作系统 | Windows 11 x64 为主目标；Windows 10 1903+ 尽力可用（非验收目标） |
| 权限 | **默认普通权限**运行，不写 HKLM、不装服务或驱动 |
| 依赖 | 除系统自带组件外无外部运行时；**不要求 Everything**（已在 1.4 排除） |
| 显示 | 支持 100%–300% 缩放；多显示器 |
| 磁盘 | 程序 <20MB；数据目录随索引/剪贴板历史增长，上限可配 |
| 网络 | **默认不出网**。仅两处可选出网：用户自填的网页搜索跳转（由浏览器完成）、用户显式点"下载站点图标" |

### 2.3 总体架构

```
                    ┌──────────────────────────────────┐
   Win32 事件源      │  主线程 (winit / eframe App::ui)   │
  ┌────────────┐    │  ┌──────────────────────────────┐ │
  │ WM_HOTKEY  │─┐  │  │ 状态机: visible / mode /      │ │
  │ 焦点变化    │ │  │  │ selection / marked / panel    │ │
  │ 托盘消息    │ │  │  └──────┬───────────────────────┘ │
  │ 命令行交接  │ │  │         │ 消费 mpsc / ArcSwap     │
  └────────────┘ │  │         ▼                          │
                 │  │  ┌──────────────────────────────┐  │
   后台线程       │  │  │ query 解析 → ProviderRegistry │  │
  ┌────────────┐ │  │  │ → matching → ranking → 结果   │  │
  │ index-scan │◄┼──┤  └──────────────────────────────┘  │
  │ icon       │ │  │         ▲                          │
  │ clipboard  │─┘  │  ┌──────┴───────────────────────┐  │
  │ hotkey-msg │    │  │ actions / launcher / params  │  │
  │ window-enum│    │  └──────────────────────────────┘  │
  └────────────┘    └──────────────────────────────────┘
             共享: config.json / 索引快照 / Knowledge / 主题
```

分层约束：

1. **UI 层不含业务判断**——匹配、排序、执行、容错都在 UI 之外，UI 只渲染 `Vec<ResultItem>` 和把输入事件转成意图。这条是阶段二能"只改视觉不改功能"的前提。
2. **数据源层互不知情**——任何数据源的失败只影响它自己（见 NFR-04）。
3. **后台线程不碰渲染上下文**——`TextureHandle` 只能在主线程创建。
4. **wgpu 候选后端必须显式排除 Vulkan**——本机 Intel 核显的 Vulkan 驱动（`igvk64.dll` 31.0.101.2140）在 wgpu 枚举适配器阶段**确定性**访问违例，进程直接以 `0xC0000005` 退出，且崩在 `AppCreator` 之前，应用层无法捕获。实现方式：`NativeOptions.wgpu_options` → `WgpuSetup::CreateNew(..).instance_descriptor.backends = Backends::DX12 | Backends::GL`（实测 5/5 正常）。这条同时给 ~~NFR-05~~（**2026-10-15 更正编号：NFR-05 是"隐私"，此处应为 NFR-04"稳定性边界"**）NFR-04 加了一个前提：**渲染上下文创建失败必须是可诊断的错误，不能是崩进程**。详见附录 E-18。
5. **（2026-10-15 新增）候选后端在"逐像素透明"上不等价，不许当作可互换的兜底**：`DX12` 走 DXGI 交换链，而 DXGI 不允许在 HWND 上创建带 alpha 的交换链（实测症状 = 半透明红呈现成暗红、四角残留黑）；`GL` 走 WGL 像素格式 + GDI 重定向面，DWM 认它的 alpha，实测可干净透出桌面。且 `Backends::DX12 | GL` 里 wgpu 优先枚举 DX12，**"允许 GL"不等于"用 GL"**。因此：阶段一**不开**窗口透明（`ViewportBuilder` 不得带 `with_transparent(true)`）；阶段二要做透明，必须把后端改成**只留** `Backends::GL` 并重新验证显隐黑闪。详见 E-18 / E-07。

### 2.4 一次交互的完整数据流

```
热键按下 → 截住抢跑按键 → 窗口可见+聚焦 → 输入变化(去抖)
  → SearchQuery 解析 → 各数据源 Search(容错) → +Boost → 独占过滤
  → 稳定排序 → 按 Uid 去重 → 截断 → 无结果则兜底 → 渲染
  → Enter → 记学习/最近/统计 → 隐藏窗口 → 按 Kind 执行 → 异常兜住
```

**顺序上的两个硬性要求**（都是参考项目踩过的坑）：

- 学习计数与"最近使用"的写回必须在**执行之前**，否则执行阻塞或失败时计数丢失，排序无法收敛。
- 窗口必须先"可见 + 聚焦"再渲染首批结果，但**渲染必须在窗口前置之前完成一帧**，否则用户会看到空框闪烁。参考项目的做法是 `DWMWA_CLOAK` 藏起、画完再露（FR-UIX-06）。

### 2.5 关键设计继承

本文把参考项目里几个"看着像细节、其实是设计决策"的点显式立为约束，避免实现时被无声改掉：

| 决策 | 出处 | 为什么不是随便定的 |
| --- | --- | --- |
| 学习排序只作用于应用的**排名**，不直接加进总分 | AHK `Knowledge` | 直接加总分让高频应用在任何查询下都靠前，新需求永远排不上 |
| 靠关键字/路径/正文命中的结果**标题不高亮** | AHK `HighlightText` | 高亮不相关字符会让人误判匹配依据 |
| 只实例化 `VisibleRows` 行、用 offset 滚动、**永不出现滚动条** | AHK `SearchWindow` | 即时模式下每帧重建几十个控件是性能塌方点；滚动条会改变内容宽度导致抖动 |
| 单个数据源异常只跳过不中断 | AHK `ProviderRegistry` | 书签文件被浏览器锁定这类事必须不影响启动程序 |
| `.lnk` 解析失败静默跳过、不超时阻塞 | AHK / 计划风险表 | 卸载残留、网络路径是常态而非异常 |
| 日志与统计**都不记录用户输入内容** | AHK `Logger` / `Usage` | 搜索词是隐私敏感度最高的数据 |
| 剪贴板临时借用（片段粘贴、选中内容操作）不写入历史 | AHK `PauseRecording` | 否则用户每粘一条片段历史就被垃圾填满 |
| 自启/SendTo 快捷方式**只删自己创建的** | AHK 2026.09.30.3 修过的 bug | 误删用户快捷方式的后果不可逆 |
| 写快捷方式前比对内容，未变不重写 | AHK（曾致开机慢 11 秒） | 启动路径上的任何 IO 都要有理由 |
| **每个功能都附带快捷键，免鼠标可达**〔2026-10-17 用户增补规则〕 | 启动器品类的核心卖点本身 | 快捷键方便才是启动器；新增功能未设计键位不算完成。现状盘点：`Ctrl+Alt+Space` 全局呼出/隐藏、`↑↓` 选择、`Enter` 运行/弹窗确定/无匹配弹新增、`Esc` 多段（关框→设置页返回→清空→隐藏）；~~托盘菜单项、SendTo 安装、批量导入等尚未配键，列入后续~~〔2026-10-17 已补键并经用户两轮改键定稿，**复测通过**（用户原话「测试正常」）：`Ctrl+N` 新建、`Ctrl+E` 编辑选中项、`Delete` 删除选中项（仅搜索框为空时生效，有输入时该键归文本编辑）、`Ctrl+Shift+D` 删除选中项（不受输入限制）、`Ctrl+D` 打开选中项所在目录（explorer /select，命令名/URL/虚拟文件夹给红 Toast 说明）、`Ctrl+I` 批量导入、`Ctrl+,` 设置页开/关；`Ctrl+S`（安装 SendTo）**同日第二轮撤销**——SendTo 从快捷键与托盘菜单撤下，改为设置页「通用」里的开关（开=安装、关=删除，只删自己创建的）。功能键均仅在窗口可见且无弹窗时生效。〕〔同日 FR-SRC-19 追加键位：`Ctrl+P` 置顶 / 取消置顶（右键菜单并设「置顶」入口），随 B 轮交真人复测〕 |

### 4.2 配置模型

单一 JSON 文件承载**全部设置与用户数据**（继承 AHK 版 `ALTRun.json` 的做法：设置与用户数据同文件，便于整体备份与迁移）。

### 4.5 路径变量与参数标记语法

**参数标记**（Delphi 版机制，本项目原样保留）：`{%p}` 用户输入的参数（占位符本体）· `{%c}` 呼出瞬间的剪贴板文本 · `{%wd}` 呼出瞬间前台窗口句柄 · `{%wt}` 其标题 · `{%wc}` 其窗口类名。参数编码类型 `ParamType`：`none` / `no_encoding` / `url_query` / `utf8_query`。带参项在列表行上必须有可见标记（继承 Delphi 的 `*` 前缀语义）。

**片段占位符**：`{date}` `{time}` `{datetime}` `{clipboard}` `{clipboard:n}` `{uuid}` `{cursor}` `{date:格式}` `{time:格式}` `{date+7}` `{date-1:格式}`（日期偏移 + `FormatTime` 式自定义格式）。

### 8.4 必须前移到阶段一的视觉相关决策

由实测数据新导出的 **4 条实现约束**（已写入 FR-SRC-02）：

1. **`%VAR%` 形态**：实测 `working_dir` 与 `icon` 存在未展开的环境变量（`%windir%\explorer.exe`），使用前必须过 `ExpandEnvironmentStringsW`，否则工作目录无效导致启动失败。

4. **扫描必须先按扩展名过滤**：把目录直接交给 `IPersistFile::Load` 返回 `0x80070005`（拒绝访问）⇒ 单文件解析失败只跳过、不中断整体扫描（对应 NFR-04）。

### E-01/E-02 阻塞根因更正与规避（2026-10-15，已闭环）

**取证手段**（不是推断）：进程内向量化异常处理器打印出错模块+偏移；PowerShell 管控生命周期做重复启动计数；`WGPU_BACKEND` 环境变量与进程内 `instance_descriptor.backends` **两条独立路径交叉验证**；读取 `igvk64.dll` 的版本资源信息；逐行核对本地 crate 源码。

**四条更正**：

1. **`igvk64.dll` 不是 OpenGL ICD，是 Intel 的 Vulkan 驱动**。版本资源 `FileDescription = "Vulkan(R) Driver for Intel(R) Graphics Accelerator"`，`ProductVersion = 31.0.101.2140`，路径 `DriverStore\FileRepository\iigd_dch.inf_amd64_...`。上一节"GL 上下文创建期崩溃"的说法作废，实际是 **wgpu 枚举/创建 Vulkan 适配器时崩**。
2. **渲染后端一直是 wgpu，不是 glow**。eframe 0.36.2 的 `default` 特性含 `wgpu`、**不含 `glow`**（`eframe-0.36.2/Cargo.toml:60-69`），`Renderer::default()` 即使两者都开也返回 `Wgpu`（`epi.rs:606-618`），而本项目 `Cargo.toml` 从未开启 `glow` ⇒ 开发计划里"渲染后端固定 glow"**从未生效，属规格与实现不一致**（新挂 E-18）。机制上：`Backends::default() = all()`（`wgpu-types-30.0.1/src/backend.rs:141`），`Backend::Vulkan = 1` 索引最小、`request_adapter` 按 `instance_per_backend.iter()` 的索引顺序枚举（`wgpu-core-30.0.1/src/instance.rs:492-496`）⇒ **默认必先试 Vulkan**。
3. **崩溃是确定性的，不是随机的**。2026-10-15 复测：默认配置下 `egui-launcher.exe` 5/5 崩、`winprobe.exe` 3/3 崩（昨天记的 4–8/10 是同一故障的不同偏移：`+0x64ea82` 写违例、`+0x630e71` 读违例）。
4. **主因已分离，虚拟显卡被排除**。停掉向日葵（`OrayIddDriver` 仍在设备列表）后仍 5/5 崩；而进程内把候选后端改为 `DX12` 或 `GL` 各 3/3 正常，并打印出真实适配器（`backend=Dx12 device_type=IntegratedGpu name="Intel(R) HD Graphics 630"`、`backend=Gl` 同），改回 `VULKAN` 立即复现同一 AV。⇒ 故障面收窄到"本机 Intel 核显的 Vulkan 驱动"这一个组件。

**规避（已落地 `src/main.rs`）**：显式 `renderer: eframe::Renderer::Wgpu` + `wgpu_options.wgpu_setup → CreateNew(..).instance_descriptor.backends = Backends::DX12 | Backends::GL`（保留 GL 兜底）。实测连跑 **5/5 正常**，截图核对窗口内容绘制正确、无黑块。**边界要说清**：当前 `CentralPanel` 是不透明底色，逐像素透明/圆角/点击穿透尚未实现，所以这次只验证到"现有窗口配置在 DX12 下渲染正确"，**不能推广为"DX12 下透明窗口也不黑闪"** —— 后者留 E-18 在阶段二复测。**（2026-10-15 这条保留判断应验：同日我用 `PrintWindow` 读到离屏帧缓冲的 alpha 正确就宣布"透明闭环、无黑块"，被用户肉眼推翻 —— DX12 下红块不半透明、四角残留黑。根因与 GL/DX12 的实测对照见 E-18；`src/main.rs` 已撤掉 `with_transparent(true)`。）**

**一条未解释的反常，标为待查**：`VK_LOADER_DRIVERS_DISABLE=igvk64.dll` 理论上应让 wgpu 跳过该 ICD 退回 DX12，实测 **4/4 仍崩**。可能是本机 Vulkan loader 不实现该变量、或 Intel manifest 的 `libraryName` 与之不匹配。**未查明前，不得把它当作可用的规避手段**（`WGPU_BACKEND` 则确认有效，其合法取值见 `wgpu-types:180-197`）。

**对排期的影响**：上一节"本机不能做 GUI 实测"的硬阻塞解除，**E-15/E-16/E-17 恢复可执行**，M2 与 M1 的窗口类实测都不再被环境挡住。仍保留一条前提：驱动/系统层面的根治（更新或回退 Intel 驱动、或换正式版 Win11）**未做**，所以正式版环境的绝对延迟复测依然要做（上一节第 1 条不变）。

### E-15 cloak 生效性实测记录（2026-10-15，注入 × DWM 遮蔽）

**运行命令**：`cargo run --bin winprobe -- hotkey 20 cloak`。探针窗口置顶于 `SHOW_POS (300,200)`，自注入 20 轮 `Ctrl+Alt+Space`（显示）→ `Ctrl+Alt+R`（隐藏），间隔 700ms；每轮下发 `DwmSetWindowAttribute(hwnd, DWMWA_CLOAK, &on, 4)`，下一帧回读 `DWMWA_CLOAKED` 与 `IsWindowVisible`，记录前台 hwnd。报告归档于 `experiments/e15-inject-cloak-hotkey-report.txt`。

**探针 hwnd**：`0x510e2`。

**结论 1（cloak 生效性）**：20/20 轮下发 `DWMWA_CLOAK=1` 后回读 `DWMWA_CLOAKED=1` 且 `IsWindowVisible=true`；下发 `=0` 后 20/20 回读 `=0`。0 次超时（600ms 门限内全部生效）。**cloak 在 DWM 合成层藏得住，但 Win32 可见语义（`WS_VISIBLE`）保留 ⇒ 不被 eframe 的 100ms 不可见重绘节流钳制**。

**结论 2（焦点归属）**：20/20 轮"按下时前台 = 探针自身 `0x510e2`" ⇒ 有效 0、抢焦点 0。这是继注入 19/19（park）、物理开局 2/2（park）之后的第三类独立证据 ⇒ **"隐藏必须显式交还焦点"这条 FR-WIN-02 硬前置对 cloak 同样成立，cloak 不自带交还效果**。
