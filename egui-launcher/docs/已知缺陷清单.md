## 五、这份清单不能声称的事

1. **不声称穷尽**。它是「三份文档自己登记过的东西」的收拢，不是对产品跑出来的新发现；一份从没被写进文档的缺陷不在这里。
2. **不声称每条都还活着**。乙档只说明「当时修了并留了证」，本轮没有重跑任何一条的回归；L-04 就是「旧登记没跟着新代码改口」的实例——本轮现读代码发现接口早已在场。
3. **不声称甲档只有 3 条**。甲档的口径是「登记在文档里、状态仍是未修、用户能撞上」；D-02 是否真在 release 产物里可复现，本轮零窗口、没验。
4. **不重判附录 E**。G-04／G-05／G-06 三条只报矛盾，不动任何一条的闭环状态——改状态需要需求方裁定或一轮新的实测。
5. **不删已撤除功能的用例**。G-07 那 4 条按历批成规保留原文，只加登记。
6. 本轮为这份清单跑的证据面：`target/dlv/scan-defects.py`（20 词 × 3 文档 = 477 命中行）、`target/dlv/tier-lines.txt`（240 行按档过滤）、`target/dlv/ee-rows.txt`（附录 E 18 行全文）、`target/dlv/scan-ee.py`（含两处按标签现找的行号）、GitHub Releases API 一次当场重读、`src/main.rs` 两处语句的行号现读、`git ls-files -- egui-launcher/experiments` 一次入库核对。
